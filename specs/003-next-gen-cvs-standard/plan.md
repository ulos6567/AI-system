## Summary

001(거래·자동화 실행 계층)과 002(분석·처방 지능 계층)이 구축한 플랫폼 위에서, 비즈니스 모델/비전 문서가 제시한 **"차세대 편의점 표준 모델"**을 하나로 정합·완성한다. 신규 도메인을 더하기보다, 흩어진 구성요소(데이터 허브 표준화·고객 대면 무대기 결제·오프라인 백업·거버넌스)를 **표준 모델로 통합**하고 비전의 KPI를 검증 가능한 성공 기준으로 고정하는 것이 본 계획의 핵심이다.

비전 문서의 두 축을 그대로 따른다:

1. **인건비 절감** — AI 카메라·센서 기반 무인/무대기 운영(고객 셀프 결제 + 오프라인 백업 결제로 가동률 방어).
2. **신선식품 폐기 손실 최소화** — 통합 데이터 허브(내부 POS + 외부 날씨·상권 + 실시간 영상)를 표준화해 001 수요예측·자동발주·002 처방의 입력 품질을 끌어올림.

세 가지 통합 경계가 본 계획을 규정한다:

1. **데이터 허브 표준화 우선** — 점포별 제각각인 상품 코드/메뉴명을 표준 코드로 통일(`mappings`/`product-mapping` 확장)해야 AI 학습 효율과 외부 연동이 성립한다. 표준화는 001/002의 선행 입력이다.
2. **무대기 결제 + 오프라인 백업은 가동률(99.99%) 계약** — 고객 셀프 결제 흐름을 완성하고, 통신·서버 장애 시에도 결제 가능한 오프라인 백업 모드(`local-buffer`)를 표준 경로로 승격한다.
3. **거버넌스는 기능이 아니라 게이트** — 비식별 처리·개인정보 암호화·동의(`consent`)·오프라인 폴백을 모든 데이터/결제 경로의 통과 조건으로 둔다.

## Technical Context

001/002와 동일 스택을 재사용한다(신규 스택 도입 없음). 비전 문서의 TO-BE 기술(Flutter/RN, Prophet/LightGBM, YOLO)은 **포트로 추상화**해 시뮬레이션·외부 연동 어느 쪽이든 교체 가능하게 둔다.

| 항목 | 결정 | 출처/근거 |
|------|------|----------|
| **언어/런타임** | Node.js 20 LTS + TypeScript 5.x | 001/002 재사용 |
| **프론트엔드(점주)** | Vue.js 3 + Pinia + Vite | 001 재사용(점주 모바일 대시보드) |
| **프론트엔드(고객)** | 셀프 결제 키오스크 뷰(동일 Vue 스택, 키오스크 모드) | 비전: 고객용 셀프 결제 |
| **백엔드** | Express.js + TypeScript, 포트·어댑터 구조 | 001 재사용 |
| **DB** | MariaDB (mysql2) | 001 재사용, 표준화 매핑·결제 테이블 증분 |
| **프록시/보안** | Nginx 리버스 프록시(보안·로드밸런싱) | 비전 TO-BE 아키텍처 |
| **컨테이너** | Docker | 비전 TO-BE, 기존 `docker/` 재사용 |
| **수요예측 엔진** | `forecast` 포트(Prophet/LightGBM 류 어댑터 교체 가능) | 001 재사용 |
| **영상 인식** | `vision` 포트(YOLO 류 어댑터 교체 가능, 시뮬레이션 우선) | 002 재사용 |
| **오프라인 백업 결제** | `local-buffer` 서비스 승격 + 동기화 잡 | 비전: 장애 시 결제 가능 |
| **인증/권한** | 001 RBAC 재사용(`middleware/rbac.ts`) | 점주·직원·고객 분리 |
| **개인정보·동의** | 기존 `consent` 서비스 게이트화 | 비전: 비식별·암호화 |
| **테스트** | Vitest(프론트) + 백엔드 통합 테스트 | 001/002 재사용 |
| **시크릿** | `.env` 분리, 평문 금지 | 보안 |

## Phase 0: Outline & Research

→ 산출물: [research.md](./research.md)

핵심 의사결정 요약:

1. **상품 코드 표준화 전략** — 점포별 원시 코드 → 표준 코드 매핑 테이블 + 정규화 규칙(유사명 매칭). 미매핑은 자동 추정하지 않고 "미매핑"으로 명시·리포트(SC-006).
2. **오프라인 백업 결제 모델** — 장애 감지(헬스체크 실패) → 로컬 버퍼에 거래 누적 → 복구 시 멱등 동기화. 이중 결제 방지 위해 거래 멱등키 사용.
3. **외부 데이터 연동** — 날씨·상권·유동인구는 `external-data` 포트로 추상화, 1차는 시뮬레이션 어댑터(시드 + 주기 잡). 포트 인터페이스는 실연동과 동일 형태.
4. **무대기 결제·대기시간 계측** — 셀프 결제 흐름에 타임스탬프 측정점 삽입(SC-004). 키오스크 모드는 점주 화면과 동일 스택, 권한·UI만 분리.
5. **거버넌스 게이트** — 영상/고객 분석은 비식별 집계만, 동의 미확보 시 수집 차단. 데이터·결제 경로 진입 전 `consent` 검사.
6. **KPI 정합** — 비전 KPI를 SC-001~007로 고정하고 `kpi` 서비스에서 단일 집계, 대시보드 단일 노출.

## Phase 2: Task Planning Approach

> 본 단계는 `/speckit.tasks`에서 산출한다. 분해 원칙(미리 정의):

1. **표준화 우선(선행)** — 데이터 허브 표준화가 001/002 입력 품질을 좌우하므로 먼저.
