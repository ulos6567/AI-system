## 기존 구현과의 재정합 (Reconciliation with 001/002) *(2026-06-10)*

구현 코드 점검 결과, 본 명세의 상당 부분이 **이미 001/002로 구현**되어 있어 003은 **신규 구축이 아니라 기존 자산 위의 얇은 보강 계층**으로 재정의한다. 신규 테이블·중복 모듈을 만들지 않는다.

| 영역 | 기존 자산(재사용) | 003 실제 작업(빈틈) |
|---|---|---|
| 표준화 | `product_master`, `product_local_mapping`, `services/product-mapping.ts`, `routes/mappings.ts` | **커버리지 % 리포트 엔드포인트**(SC-006) 신규 |
| 외부 데이터 | `ports/signal.ts` + `adapters/signal/weather-kma.ts`·`mock.ts` + `jobs/signal-poll.ts` (날씨) | 상권·유동인구 신호는 동일 `signal` 포트로 **확장**(시뮬레이션) |
| 셀프 결제 대기시간 | (없음) | **`checkout_metric` 계측**(SC-004) 신규 — 유일한 신규 테이블 |
| 오프라인 백업 | `services/local-buffer.ts`(메모리+JSONL, 헬스워커 flush) | 기존 방식 재사용. DB 테이블 신설 안 함 |
| KPI | `services/kpi.ts`(매출·폐기율·`forecast_mape`=정확도) + `routes/dashboard.ts` | uptime·커버리지·거버넌스 지표를 **대시보드에 통합 노출** |
| 거버넌스 | `routes/consent.ts`, `middleware/pii-guard.ts` | 기존 게이트 재사용 |

**FR-002 재정합**: 기존 매핑은 자동 후보를 산출하되 **신뢰도 미달·미매치는 `status='pending'`(미확정)으로 표시**하고 검토 큐에 노출한다. 이는 "추정값을 확정 처리하지 않는다"는 원래 의도와 **동등**하다 — 따라서 FR-002는 "자동 추정값을 *확정*으로 처리 금지, 미확정은 명시"로 해석한다(아래 FR-002 갱신 반영).

**data-model.md / contracts/api.yaml 주의**: 그 문서들이 명명한 `standard_product`·`product_code_mapping`·`offline_payment_buffer`는 **각각 기존 `product_master`·`product_local_mapping`·`local-buffer(JSONL)`로 대체**한다(신규 테이블 아님). 유일한 신규 테이블은 `checkout_metric`이다.

## 비즈니스 모델 요약 (Business Model Summary)

편의점 고정비의 두 축인 **인건비**와 **신선식품 폐기 손실**을 데이터·AI로 최소화해 가맹점 영업이익률을 극대화하는 라이프스타일 플랫폼이다. 001이 거래·자동화의 실행을, 002가 분석·처방의 지능을 담당한다면, 본 명세는 이를 **현장에서 동작하는 표준 모델로 정합**한다: 점포별 제각각인 데이터를 표준화하는 **통합 데이터 허브**, 고객의 **무대기 셀프 결제**, 장애에도 끊기지 않는 **오프라인 백업 결제**, 그리고 비식별·동의를 강제하는 **거버넌스 게이트**.

| 구분 | 핵심 내용 |
|------|----------|
| **타깃 고객** | 가맹점주·본사 운영자, 매장 직원, 최종 매장 고객 |
| **핵심 가치** | 인건비·폐기 손실 절감, 무대기 결제 경험, 장애 시에도 끊기지 않는 운영 연속성 |
| **수익 모델** | 영업이익 개선분 공유 + B2B 솔루션 라이선스 + 상권·소비 트렌드 데이터 판매 |
| **핵심 파트너** | POS·결제 기업, 소상공인 연합회·지자체, 식자재·물류 기업 |
| **주요 장벽** | 점포별 데이터 비정형성(상품 코드 제각각), 초기 도입 비용 부담, 개인정보 리스크, 시스템 의존성(장애·유출) |

## User Scenarios & Testing *(mandatory)*

### Primary User Story

**가맹점주 김 사장**은 도입 첫 주, 본사가 제공한 표준 상품 마스터에 점포의 제각각인 상품 코드를 매핑해 **데이터 표준화 커버리지를 95% 이상**으로 끌어올린다. 그 결과 수요예측·자동발주(001)의 입력 품질이 올라가 폐기율이 눈에 띄게 줄어든다. 야간에는 고객이 직원 없이 **셀프 결제 키오스크로 대기 없이** 결제하고, 새벽에 통신 장애가 발생해도 결제가 **오프라인 백업 모드**로 끊김 없이 이어진 뒤 복구 시 자동·안전하게 동기화된다. 김 사장은 아침에 모바일에서 **폐기율·객단가·예측 정확도·결제 대기시간·가동률**을 한 화면으로 확인한다. 이 모든 과정에서 고객 영상·행동 데이터는 **비식별 처리**되고 동의 없이는 수집되지 않는다.

### Acceptance Scenarios

1. **(표준화)** 점포 원시 상품 코드 집합이 주어지면, 시스템은 표준 코드로 매핑하고 매핑 불가 항목을 **"미매핑"으로 명시**하며 커버리지 비율을 리포트한다. (추정 매핑은 하지 않는다.)
2. **(셀프 결제)** 고객이 셀프 결제를 시작하면, 시스템은 결제를 완료하고 **결제 시작~완료 대기시간을 계측·기록**한다.
3. **(오프라인 백업)** 결제 중 통신·서버 장애가 감지되면, 시스템은 결제를 로컬 버퍼에 안전하게 적재해 **결제 연속성을 유지**하고, 복구 후 **중복 없이(멱등) 동기화**한다.
4. **(외부 데이터)** 외부 신호(날씨·상권·유동인구)가 표준 입력으로 수집되면, 수요예측의 입력으로 결합되어 **예측 정확도가 계측**된다.
5. **(KPI 가시화)** 점주가 대시보드를 열면, 폐기율·객단가·예측 정확도·결제 대기시간·가동률·표준화 커버리지·거버넌스 준수 지표가 **한 화면에 통합 표시**된다.
6. **(거버넌스 게이트)** 동의가 확보되지 않은 고객 데이터는 **수집·처리되지 않으며**, 영상·행동 분석 결과는 **비식별 집계 형태로만** 제공된다.

### Edge Cases

- 표준 상품 마스터에 대응 항목이 없는 신상품 → "미매핑"으로 분류, 자동 추정 금지, 본사 검토 큐로 회부.
- 장애 복구 후 동일 거래가 버퍼와 정식 경로에 모두 존재 → 멱등키로 1건만 반영, 중복 결제 차단.
- 외부 데이터 제공이 일시 중단 → 마지막 유효 신호 또는 "데이터 없음"으로 표시, 예측은 내부 데이터로 폴백.
- 셀프 결제 중도 이탈(고객 포기) → 미완료 거래로 종료, 대기시간 통계에서 제외 또는 별도 분류.
- 동의 철회 → 이후 수집 즉시 중단, 기수집 데이터는 비식별·삭제 정책에 따름.

## Requirements *(mandatory)*

### Functional Requirements

#### 데이터 허브 표준화 (US1, P1)

- **FR-001**: 시스템은 점포별 원시 상품 코드를 **표준 상품 코드로 매핑**할 수 있어야 한다.
- **FR-002**: 시스템은 자동 매핑 후보의 **신뢰도 미달·미매치 항목을 `pending`(미확정)으로 명시**하고 검토 큐에 노출해야 하며, **추정값을 확정(`confirmed`)으로 자동 처리해서는 안 된다**. (기존 `product_local_mapping.status` 재사용 — 재정합 참조)
- **FR-003**: 시스템은 점포·전체 단위의 **표준화 커버리지 비율과 미매핑 목록을 리포트**해야 한다.
- **FR-004**: 시스템은 표준 상품 마스터를 보유하고, 점주가 매핑을 등록·수정할 수 있어야 한다.

#### 무대기 셀프 결제 (US2, P1)

- **FR-005**: 시스템은 고객이 직원 개입 없이 **셀프 결제를 완료**할 수 있게 해야 한다.
- **FR-006**: 시스템은 각 셀프 결제의 **시작~완료 대기시간을 계측·기록**해야 한다.
- **FR-007**: 시스템은 셀프 결제 경로 진입 시 **거버넌스 게이트(동의·비식별)를 통과**하도록 강제해야 한다.

#### 오프라인 백업 결제 (US3, P2)

- **FR-008**: 시스템은 통신·서버 장애를 감지하면 결제를 **로컬 버퍼에 적재**해 결제 연속성을 유지해야 한다.
- **FR-009**: 시스템은 각 버퍼 거래에 **멱등 식별자**를 부여해 이중 결제를 방지해야 한다.
- **FR-010**: 시스템은 장애 복구를 감지하면 버퍼 거래를 정식 거래로 **멱등 동기화**하고, 동기화 상태를 조회 가능하게 해야 한다.

#### 외부 데이터 연동 (US4, P2)

- **FR-011**: 시스템은 외부 신호(**날씨·상권·유동인구**)를 표준 입력 형태로 수집·저장해야 한다.
- **FR-012**: 시스템은 수집된 외부 신호를 **수요예측의 입력으로 결합**하고 예측 정확도를 계측해야 한다.
- **FR-013**: 외부 데이터 제공이 중단되면 시스템은 **내부 데이터로 폴백**하고 상태를 표시해야 한다.

#### KPI 통합 대시보드 (US5, P3)

- **FR-014**: 시스템은 **폐기율·객단가/매출·예측 정확도·결제 대기시간·가동률·표준화 커버리지·거버넌스 준수** 지표를 단일 집계로 산출해야 한다.
- **FR-015**: 시스템은 위 지표를 점주에게 **한 화면(통합 대시보드)으로** 제공해야 한다.

#### 거버넌스 (횡단)

- **FR-016**: 시스템은 고객 영상·행동 데이터를 **비식별 집계 형태로만** 처리·제공해야 한다.
- **FR-017**: 시스템은 **동의가 확보되지 않은** 고객 데이터를 수집·처리해서는 안 되며, 동의 철회 시 이후 수집을 중단해야 한다.
- **FR-018**: 시스템은 표준화·결제·동기화·동의 관련 주요 이벤트를 **감사 기록**으로 남겨야 한다.

### Key Entities

- **표준 상품(Standard Product)**: 본사 기준 상품 마스터. 표준 코드, 명칭, 분류.
- **상품 코드 매핑(Product Code Mapping)**: 점포 원시 코드 ↔ 표준 코드, 신뢰도, 상태(매핑/미매핑).
- **오프라인 결제 버퍼(Offline Payment Buffer)**: 장애 중 적재된 거래. 멱등키, 동기화 상태.
- **결제 대기 지표(Checkout Metric)**: 셀프 결제 건별 대기시간·시각.
- **외부 신호(External Signal)**: 날씨·상권·유동인구 표준 입력. 출처, 시각, 값.
- **KPI 스냅샷(KPI Snapshot)**: SC-001~007 집계 결과의 시점별 스냅샷.
- **동의(Consent)**: 고객 데이터 수집·처리 동의 상태(기존 자산 재사용).

## Success Criteria *(mandatory)*

- **SC-001**: 표준화된 수요예측·자동발주가 적용된 매장에서 **신선식품 폐기율이 40% 이상 감소**한다.
- **SC-002**: 적용 매장의 **객단가·총매출이 15% 이상 상승**한다.
- **SC-003**: 외부 신호가 결합된 **수요 예측 정확도가 90% 이상**이다. (정확도 = **100 − MAPE**, 품목·일 단위 평균 절대 백분율 오차 기준. research §R7 참조)
- **SC-004**: **피크타임 셀프 결제 대기시간이 건당 10초 이내**다.
- **SC-005**: 통신·서버 장애 시에도 결제 연속성이 유지되어 **시스템(결제) 가동률이 99.99%** 이상이다.
- **SC-006**: 점포 간 **상품 코드 표준 매핑 커버리지가 95% 이상**이며, 미매핑 항목은 명시된다.
- **SC-007**: 고객 영상·행동 데이터가 **100% 비식별 처리**되고, **동의 미확보 데이터는 수집되지 않는다**.

## Assumptions

- **표준 상품 마스터 소유**: 1차는 **본사 기준**으로 마스터를 관리하며, 점포별 커스텀 매핑은 후속 단계로 미룬다.
- **외부 데이터 공급**: 1차는 **시뮬레이션/시드 데이터**로 동작하고, 실제 제공처 연동은 표준 입력 인터페이스를 통해 후속 연결한다(실연동 시 본 명세 변경 불요).
- **무인 하드웨어**: 무인 게이트·중량 센서·AI 카메라 등 **물리 하드웨어 도입은 1차 범위 제외**(표준 입력 인터페이스만 정의, 시뮬레이션으로 검증).
- **폐기율 목표**: 비전 요약의 50%와 KPI의 40% 중 **보수적 40%(SC-001)**를 채택하며, 상향은 실증 후 조정한다.
- **결제 연동**: 기존 POS·결제 자산을 통한 결제 처리를 전제하며, 셀프 결제는 그 위의 흐름·계측을 추가한다.
- **데이터 보존·삭제**: 동의 철회·비식별 처리는 업계 표준 관행을 따른다.

## Dependencies

- **001-ai-store-ops**: 수요예측·자동발주·동적 가격·POS/결제·실시간 이벤트 실행 계층 (표준화 데이터의 소비처).
- **002-ai-intelligence-suite**: 분석·처방·이상감지·비서 지능 계층 (KPI·거버넌스 일부 공유).

## Out of Scope
