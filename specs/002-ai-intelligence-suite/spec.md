## 비즈니스 모델 요약 (Business Model Summary)

001(AI 점포 운영 플랫폼)이 **거래·자동화의 실행 계층**을 담당한다면, 본 명세는 그 위에서 동작하는 **"분석→처방→자동 실행→검증"의 지능 계층**을 정의한다. 단순 예측("매출이 감소할 것입니다")에 그치지 않고 **구체적 행동 가이드("OOO 상품을 OO% 인하하고 당일 한정 프로모션을 실행하세요")**를 자동으로 제시·실행하며, Vision AI 기반 고객 분석·이상 징후 감지·IoT 예지보전·LLM 경영 비서·인력 스케줄러를 통합한다.

| 구분 | 핵심 내용 |
|------|----------|
| **타깃 고객** | 가맹점주·본사 운영자(슈퍼바이저), 매장 직원, 최종 매장 고객 |
| **핵심 가치** | 의사결정 부담 제거(처방형 가이드), 손실·사고 예방, 데이터 시각화로 운영 가시성 확보 |
| **수익 모델** | 영업이익 개선분 공유 + 인텔리전스 프리미엄 구독(분석·예지보전·AI 비서) |
| **핵심 파트너** | 001 플랫폼 데이터 허브, 기상·상권 데이터 제공처, 보안 관제·유지보수 사업자 |
| **주요 장벽** | 영상 데이터 개인정보 리스크, 처방의 신뢰성·설명가능성, 소상공인의 분석 리터러시 |

## Clarifications

### Session 2026-06-05

- Q: Vision AI(동선 히트맵·이상감지)와 IoT 예지보전의 데이터 처리 방식은? → A: 시뮬레이션/데모 데이터 — 실제 영상·센서 처리 없이 시드/시뮬레이션 데이터로 동작하며, 표준 입력 인터페이스는 추후 실제 연동을 위해 정의만 한다.
- Q: LLM 기반 AI 경영비서의 응답 생성 방식은? → A: 실제 외부 LLM API 연동(RAG식) — 플랫폼 데이터를 근거로 외부 LLM이 자연어 답변을 생성한다.
- Q: 처방형(Prescriptive) 액션의 실행 권한 모델은? → A: 항상 점주 승인 필수 — 모든 처방은 제안만 하며, 점주의 명시적 승인(원클릭 포함) 없이는 실행되지 않는다.

## User Scenarios & Testing *(mandatory)*

### Primary User Story

**가맹점주 박 사장**은 001 플랫폼으로 자동 발주·동적 가격까지는 자동화했지만, "그래서 지금 무엇을 해야 하는가"를 스스로 판단하기 어렵다. 본 인텔리전스 계층 도입 후, 박 사장은 아침에 앱을 열면 **풍부한 데이터 대시보드**와 함께 **오늘의 처방형 액션 카드**(예: "삼각김밥 재고가 폐기 위험 — 14시부터 20% 인하 + 인근 앱 사용자 푸시 권장, 예상 추가 매출 ₩42,000")를 받는다. 카드의 **'실행' 버튼 한 번**으로 가격·프로모션이 적용되고, 며칠 뒤 **처방의 실제 효과**가 자동 검증되어 리포트된다. 동시에 매장 CCTV는 **결제 없이 상품을 가방에 넣는 행위**를 감지해 박 사장 폰으로 즉시 알림을 보내고, 냉장 쇼케이스의 **온도 이상 패턴**을 사전 경고해 신선식품 대량 폐기를 막는다. 박 사장은 챗봇에 **"오늘 제일 많이 팔린 상품이 뭐야?"**라고 물어 즉시 답을 얻는다.

### Acceptance Scenarios

1. **처방형(Prescriptive) 액션 가이드**
   - **Given** 매출·재고·외부 데이터로부터 위험·기회 신호(매출 감소 예측, 폐기 위험, 수요 급증 등)가 감지되면
   - **When** 시스템이 일일 운영 인사이트를 생성하면
   - **Then** 각 신호에 대해 **구체적 행동(대상 상품·조정 폭·실행 시점·예상 효과)**을 담은 처방 카드가 우선순위 순으로 제시된다.
   - **And** 점주는 카드를 **원클릭으로 실행**하거나, 수정 후 실행하거나, 거절(사유 선택)할 수 있다.

2. **처방 효과 자동 검증(Closed-loop)**
   - **Given** 점주가 처방을 실행한 후
   - **When** 사전 정의된 검증 기간(예: 당일 마감 또는 7일)이 경과하면
   - **Then** 시스템은 **예상 효과 대비 실제 효과**(매출·폐기·객단가 변화)를 비교한 검증 리포트를 자동 생성한다.
   - **And** 검증 결과는 이후 처방 추천 정확도 개선에 반영된다.

3. **데이터 표출·풍부한 시각화 대시보드**
   - **Given** 점주·본사 운영자가 대시보드에 접속하면
   - **When** 기간·점포·카테고리 필터를 선택하면
   - **Then** 매출·재고 회전·폐기·객단가·예측 추이 등이 **차트·KPI 카드·실제 상품 이미지**와 함께 실시간으로 표출된다.
   - **And** 데모/시연 환경에서도 실제 사업장과 유사한 풍부한 데이터(상품 200개 이상)가 채워져 빈 화면이 노출되지 않는다.

4. **Vision AI 고객 동선 히트맵·행동 분석**
   - **Given** 매장 카메라가 비식별 동선·체류 데이터를 수집한 상태에서
   - **When** 점주가 분석 화면을 열면
   - **Then** 매대별 체류 시간·이동 동선이 **히트맵**으로 시각화되고, 비효율 매대 배치에 대한 개선 제안이 제공된다.
   - **And** 특정 상품 앞 머뭇거림·집었다 내려놓기 등의 관심 행동이 집계되어 연령대·성별별(추정·비식별) 선호 통계로 제공된다.

5. **AI 이상 징후 감지·실시간 도난 방지**
   - **Given** 매장이 (무인 포함) 운영 중인 상태에서
   - **When** 미결제 반출, 취객 소란, 사용자 쓰러짐, 야간 무단 침입 등 이상 행동이 감지되면
   - **Then** 점주 스마트폰에 **상황 유형·위치·캡처와 함께 즉시 팝업 알림**이 발송되고, 사전 설정된 경우 보안 관제처에 자동 전파된다.
   - **And** 모든 이상 감지 이벤트는 오탐 표시·대응 결과와 함께 이력으로 보존된다.

6. **IoT 장비 예지보전(Predictive Maintenance)**
   - **Given** 냉장고·쇼케이스 등 장비의 온도·전력 소모 패턴이 상시 모니터링되는 상태에서
   - **When** 정상 범위를 벗어나는 추세·이상 패턴이 감지되면
   - **Then** 시스템은 **고장 가능성·예상 시점·권장 조치**를 점주에게 사전 경고한다.
   - **And** 임계 위험(예: 냉장 온도 급상승)은 즉시 알림으로 격상되어 신선식품 대량 폐기·화재 리스크를 예방한다.

7. **LLM 기반 대화형 AI 경영 비서**
   - **Given** 점주가 복잡한 분석 도구 사용법을 모를 때
   - **When** 챗봇 인터페이스에 자연어로 질문하면("오늘 제일 많이 팔린 상품?", "내일 날씨 고려 시 샌드위치 몇 개 발주?", "이번 달 예상 마진?")
   - **Then** AI 비서가 플랫폼 데이터를 근거로 **즉시 답변**하고, 가능한 경우 관련 처방 액션으로 연결한다.
   - **And** 답변은 근거 데이터(출처·기간)를 함께 제시하며, 답할 수 없는 질문은 그 한계를 명확히 고지한다.

8. **지능형 인력 최적화 스케줄러**
   - **Given** 시간대별 예상 방문객·매출 흐름이 예측된 상태에서
   - **When** 점주가 주간 근무 스케줄 작성을 요청하면
   - **Then** 피크/한산 시간대를 구분해 **비용 효율적인 시프트 초안**을 자동 생성하고, 직원 가용성·법정 근로 제약을 반영한다.
   - **And** 점주는 초안을 수정·확정할 수 있고, 확정 스케줄과 예상 인건비가 함께 표시된다.

### Edge Cases

- **처방 신뢰도 부족**: 데이터가 부족하거나 신뢰도가 임계치 미만인 처방은 '참고용'으로 표시하고 자동 실행 대상에서 제외한다.
- **처방 충돌**: 동시에 상충하는 처방(예: 인하 vs. 품절 대비 보류)이 발생하면 시스템이 우선순위·예상 효과를 근거로 단일 권고로 정리해 제시한다.
- **영상 개인정보**: 히트맵·행동 분석은 비식별 데이터만 사용하며, 안면 등 식별 가능 데이터는 별도 명시 동의 없이는 수집·저장하지 않는다.
- **이상 감지 오탐**: 도난·사고 오탐이 임계치를 초과하면 민감도 자동 조정을 제안하고, 점주는 이벤트별로 오탐 피드백을 줄 수 있다.
- **카메라·센서 장애**: 분석용 카메라·IoT 센서가 오프라인이면 해당 분석 기능은 '데이터 없음'으로 명확히 표시하고, 001의 핵심 결제·발주 기능에는 영향을 주지 않는다.
- **AI 비서 환각**: 데이터로 뒷받침되지 않는 답변은 생성하지 않으며, 불확실한 경우 추정임을 명시한다.
- **스케줄 제약 위반 불가**: 법정 휴게·연속근무 한도 등 제약을 만족하는 스케줄을 만들 수 없으면 위반 항목을 명시하고 점주 결정을 요청한다.
- **상품 이미지 부재**: 실제 상품 이미지가 없는 품목은 카테고리 대표 플레이스홀더로 대체해 화면 일관성을 유지한다.

## Requirements *(mandatory)*

### Functional Requirements

#### A. 처방형 인텔리전스 (Prescriptive)

- **FR-001**: 시스템은 매출·재고·외부 데이터로부터 위험·기회 신호를 탐지하고, 신호별로 **대상·조정 폭·실행 시점·예상 효과**를 포함한 처방형 액션을 생성해야 한다.
- **FR-002**: 시스템은 처방 액션을 **우선순위(예상 효과·긴급도 기준)** 순으로 정렬하여 제시해야 한다.
- **FR-003**: 모든 처방은 **제안 상태로만 생성**되며, 점주의 명시적 승인 없이 자동 실행되어서는 안 된다. 점주는 처방을 **원클릭 실행, 수정 후 실행, 또는 사유와 함께 거절**할 수 있어야 한다. (신뢰도가 높은 처방도 자동 실행 대상이 아니다)
- **FR-004**: 시스템은 실행된 처방에 대해 검증 기간 경과 후 **예상 대비 실제 효과**를 비교한 검증 리포트를 자동 생성해야 한다.
- **FR-005**: 시스템은 검증 결과를 후속 처방 추천 품질 개선에 반영해야 한다.
- **FR-006**: 각 처방에는 **판단 근거(어떤 데이터·신호로 도출되었는지)**가 함께 제시되어야 한다.

#### B. 데이터 표출·시각화

- **FR-007**: 시스템은 매출·재고 회전·폐기·객단가·예측 추이 등을 **차트·KPI 카드 형태로 실시간 표출**하는 대시보드를 제공해야 한다.
- **FR-008**: 대시보드는 **기간·점포·카테고리** 필터링을 지원해야 한다.
- **FR-009**: 시스템은 상품 정보를 **실제 상품 이미지와 함께** 표출해야 하며, 이미지가 없는 품목은 카테고리 대표 이미지로 대체해야 한다.
- **FR-010**: 시연·데모 환경에서도 **실제 사업장 수준의 풍부한 데이터(상품 200개 이상, 유형별·사용자별)**가 표출되어 빈 화면이 발생하지 않아야 한다.

#### C. Vision AI 고객 분석

> **데이터 처리 범위**: 본 명세에서 Vision AI 분석은 **시뮬레이션/데모 데이터**로 동작한다. 실제 카메라 영상 처리는 수행하지 않으며, 추후 실제 연동을 위한 표준 입력 인터페이스(이벤트 형식)만 정의한다.

- **FR-011**: 시스템은 비식별 동선·체류 데이터(시뮬레이션 포함)를 기반으로 매대별 **히트맵**을 생성·시각화해야 한다.
- **FR-012**: 시스템은 히트맵 분석 결과를 근거로 **매대 배치 개선 제안**을 제공해야 한다.
- **FR-013**: 시스템은 상품 앞 관심 행동(머뭇거림·집었다 내려놓기 등)을 집계하고, 추정 연령대·성별별(비식별) 선호 통계를 제공해야 한다.

#### D. 이상 징후 감지·보안

> **데이터 처리 범위**: 이상 감지 또한 **시뮬레이션/데모 데이터** 기반으로 동작하며, 실제 영상 분석 대신 표준 이상 이벤트 입력 인터페이스를 정의한다.

- **FR-014**: 시스템은 미결제 반출·소란·쓰러짐·무단 침입 등 이상 행동(시뮬레이션 이벤트 포함)을 감지하고, **30초 이내** 점주에게 상황 유형·위치·캡처와 함께 알림해야 한다.
- **FR-015**: 시스템은 사전 설정 시 이상 이벤트를 **외부 보안 관제처로 자동 전파**할 수 있어야 한다.
- **FR-016**: 시스템은 모든 이상 감지 이벤트를 오탐 표시·대응 결과와 함께 **이력으로 보존**해야 하며, 점주의 오탐 피드백을 받아 민감도를 조정할 수 있어야 한다.

#### E. IoT 예지보전

> **데이터 처리 범위**: 장비 센서 데이터는 **시뮬레이션/데모 데이터**로 공급되며, 실제 IoT 게이트웨이 연동 대신 표준 센서 입력 인터페이스를 정의한다.

- **FR-017**: 시스템은 냉장고·쇼케이스 등 장비의 온도·전력 패턴(시뮬레이션 포함)을 상시 모니터링하고, 이상 추세 감지 시 **고장 가능성·예상 시점·권장 조치**를 사전 경고해야 한다.
- **FR-018**: 시스템은 임계 위험 상황을 일반 경고보다 상위 등급의 즉시 알림으로 격상해야 한다.

#### F. AI 경영 비서

- **FR-019**: 시스템은 자연어 질문에 플랫폼 데이터를 근거로 답하는 **대화형 AI 비서**를 제공해야 하며, 답변 생성은 **외부 LLM 서비스 연동(RAG 방식: 플랫폼 데이터를 근거 컨텍스트로 제공)**으로 수행한다.
- **FR-020**: AI 비서의 답변에는 **근거 데이터(출처·기간)**가 함께 제시되어야 하며, 답할 수 없는 질문은 한계를 고지해야 한다.
- **FR-021**: AI 비서는 가능한 경우 답변을 관련 **처방 액션 또는 화면**으로 연결해야 한다.

#### G. 인력 최적화 스케줄러

- **FR-022**: 시스템은 시간대별 예상 방문객·매출을 기반으로 **비용 효율적 근무 시프트 초안**을 자동 생성해야 한다.
- **FR-023**: 스케줄러는 직원 가용성과 법정 근로(휴게·연속근무 한도 등) 제약을 반영해야 하며, 제약을 만족할 수 없으면 위반 항목을 명시해야 한다.
- **FR-024**: 점주는 생성된 스케줄을 수정·확정할 수 있어야 하며, 확정 시 **예상 인건비**가 함께 표시되어야 한다.

#### H. 권한·보안·컴플라이언스

- **FR-025**: 본 계층의 모든 기능은 001 플랫폼의 역할 기반 접근 권한 체계를 따라 역할별로 노출·제어되어야 한다.
- **FR-026**: 영상 기반 분석은 비식별 데이터만 사용하며, 식별 가능 데이터 수집은 명시적 동의 절차를 전제로 한다.
- **FR-027**: 처방의 자동/수동 실행, AI 비서 응답, 이상 감지 대응 등 모든 의사결정·조치 이력은 감사 가능한 형태로 보존되어야 한다.

### Key Entities *(데이터 중심)*

- **운영 신호(Operational Signal)**: 매출·재고·외부 데이터에서 탐지된 위험·기회 신호. 유형·강도·관련 상품/점포를 포함.
- **처방 액션(Prescriptive Action)**: 신호에서 도출된 권고. 대상·조정 폭·실행 시점·예상 효과·근거·상태(제안·실행·거절)를 포함.
- **처방 검증(Action Outcome)**: 실행된 처방의 예상 대비 실제 효과 비교 결과.
- **고객 행동 인사이트(Behavior Insight)**: 동선·체류·관심 행동에서 도출된 비식별 집계(히트맵·선호 통계).
- **이상 이벤트(Anomaly Event)**: 도난·소란·사고·침입 등 감지 이벤트. 유형·위치·캡처·오탐 여부·대응 결과를 포함.
- **장비 상태(Device Health)**: IoT 장비의 온도·전력 등 모니터링 지표와 예지보전 경고 이력.
- **AI 대화 이력(Assistant Conversation)**: 질문·답변·근거 데이터·연결된 액션을 포함하는 비서 상호작용 기록.
- **근무 스케줄(Work Schedule)**: 시프트 초안·확정본·예상 인건비·제약 충족 여부.
- **상품 미디어(Product Media)**: 상품과 연결된 실제 이미지/대체 이미지 메타데이터.

## Success Criteria *(mandatory)*

### Measurable Outcomes

#### 처방·의사결정

- **SC-001**: 점주에게 제시된 처방 액션의 **채택(실행)률이 40% 이상**이다.
- **SC-002**: 실행된 처방의 **예상 효과 대비 실제 효과 적중률(±20% 이내)이 70% 이상**이다.
- **SC-003**: 점주의 **일일 의사결정 소요 시간이 도입 전 대비 50% 이상 단축**된다.

#### 손실·사고 예방

- **SC-004**: IoT 예지보전 경고를 통해 **장비 고장으로 인한 신선식품 대량 폐기 사건이 도입 전 대비 60% 이상 감소**한다.
- **SC-005**: 이상 감지 알림이 발생 후 **30초 이내** 점주에게 도달하는 비율이 **99% 이상**이다.
- **SC-006**: 이상 감지의 **오탐률이 운영 4주 이후 10% 이하**로 안정화된다.

#### 고객 경험·운영 가시성

- **SC-007**: 히트맵 분석 기반 매대 재배치 적용 매장에서 **추천 매대의 체류·구매 전환이 측정 가능하게 개선**된다(도입 전 대비 +10% 이상).
- **SC-008**: 대시보드 주요 화면이 **3초 이내** 로딩되며, 데모 환경에서 **빈 화면(데이터 없음) 노출이 0건**이다.
- **SC-009**: 상품 화면에서 **실제/대체 이미지 표출 커버리지가 100%**(빈 이미지 없음)이다.

#### AI 비서·인력

- **SC-010**: AI 비서가 **근거 데이터를 포함한 답변을 제공하는 비율이 95% 이상**이며, 환각성(근거 없는) 답변 비율이 2% 이하이다.
- **SC-011**: 자동 생성 스케줄이 **법정 근로 제약을 100% 준수**하며, 점주의 수정 없이 채택되는 비율이 50% 이상이다.

#### 감사·컴플라이언스

- **SC-012**: 처방 실행·AI 응답·이상 대응의 **의사결정 이력 보존율이 100%**이다.
- **SC-013**: 영상 기반 분석에서 식별 가능 개인정보의 **무동의 저장 0건**을 유지한다.

## Assumptions

- 본 계층은 001(AI 점포 운영 플랫폼)이 제공하는 데이터 허브·역할 권한·알림 채널 위에서 동작한다.
- **Vision AI·이상 감지·IoT 예지보전은 본 명세 범위에서 시뮬레이션/데모 데이터로 동작**한다. 실제 하드웨어 연동은 표준 입력 인터페이스 정의까지만 다루며, 실 영상·센서 처리는 후속 단계 의제이다.
- 외부 데이터(날씨·유동 인구·이벤트)는 001과 동일한 합법적 경로로 확보된다.
- 시연/데모 환경의 풍부한 데이터는 날짜 상대 생성 시드 스크립트로 충전되며 주기적으로 갱신된다.
- **AI 비서는 외부 LLM 서비스에 의존**하며, 해당 서비스의 가용성·비용·데이터 전송 시 개인정보 비식별화를 전제로 운영된다.
- 처방 엔진은 설명가능성(근거 제시)을 전제로 운영되며, **모든 처방은 점주 승인 후에만 실행**된다(자동 실행 없음).

---

## Dependencies

- **001 플랫폼**: POS·재고·거래·예측·가격·발주 데이터와 역할 권한·알림 인프라.
- **외부 LLM 서비스**: AI 경영비서의 자연어 답변 생성을 위한 LLM API 제공처.
- **외부 데이터 제공처**: 기상·유동 인구·상권 데이터.
- **보안 관제·유지보수 사업자**: 이상 이벤트 전파 및 현장 대응.
- **법무·컴플라이언스**: 개인정보보호법(영상·행동 데이터, LLM 전송 데이터), 근로기준법(스케줄러).

---

## Out of Scope

- **하드웨어 설치·운영 자체**: 카메라·센서·IoT 게이트웨이의 물리 설치·유지보수는 본 명세 대상이 아니다(001/보조금 사업 영역).
- **외부 보안 관제 플랫폼 구축**: 이상 이벤트를 외부로 전파하는 인터페이스까지 제공하며, 관제 센터 자체는 구축하지 않는다.
- **급여·노무 정산 시스템**: 스케줄러는 시프트·예상 인건비까지 산출하며, 실제 급여 정산·세무 처리는 범위 밖이다.
- **완전 자율 무인 운영**: 처방의 완전 자동 실행(점주 개입 0)은 신뢰도 검증 후 후속 단계 의제이다.
